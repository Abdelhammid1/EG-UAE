# منصتي — النظام المحاسبي والإداري

نظام محاسبي وإداري متكامل (مصر والإمارات) — Flask + PostgreSQL/SQLite.
راجع `IMPLEMENTATION_PLAN.md` للخطة الكاملة و`مواصفات التنفيذ...md` للمرجع.

## التشغيل محليًا (بدون أي إعداد إضافي)

يعمل على SQLite مباشرة — لا حاجة لـ Docker أو PostgreSQL أثناء التطوير.

```bash
python -m venv .venv
./.venv/Scripts/pip install -r requirements.txt   # Windows
# مصدر البيئة
cp .env.example .env

# إنشاء قاعدة البيانات وزرع البيانات
./.venv/Scripts/python -m flask --app wsgi seed

# التشغيل
./.venv/Scripts/python -m flask --app wsgi run --debug
```

ثم افتح <http://127.0.0.1:5000>.

### بيانات الدخول التجريبية
| المستخدم | الدور | الدخول |

## الاختبارات

```bash
./.venv/Scripts/python -m pytest tests/ -q
```

تختبر: دقة المبالغ العشرية، رفض خلط العملات، سجل الإعدادات (زمني + تدقيق + إقفال)،
عدم قابلية سجل التدقيق للتعديل، نموذج الصلاحيات، وتدفقات الدخول.

## النسخ الاحتياطي والاستعادة (§15.2.6)

```bash
# نسخة احتياطية (SQLite: نسخ متسق أثناء التشغيل · PostgreSQL: pg_dump)
./.venv/Scripts/python -m flask --app wsgi backup --dir backups

# فحص السلامة بعد الاستعادة (يتحقق من توازن ميزان المراجعة)
./.venv/Scripts/python -m flask --app wsgi check-integrity
```

**الاستعادة:** SQLite — أوقف التطبيق وانسخ ملف `backups/marsoud-*.sqlite` فوق
`instance/marsoud.sqlite`. PostgreSQL — `pg_restore --clean --dbname <URL> backups/marsoud-*.dump`.
بعد الاستعادة شغّل `check-integrity` للتأكد.

## الإنتاج (لاحقًا)

عيّن `DATABASE_URL` إلى PostgreSQL و`FLASK_ENV=production`، وثبّت الحزم الإنتاجية
المعلّقة في `requirements.txt` (psycopg, redis, rq, gunicorn, WeasyPrint).

## ما تم إنجازه

### المرحلة 0 — الأساس
- طبقة المبالغ المالية: `Decimal` دقيق على SQLite وPostgreSQL، قاعدة تقريب موحدة، ثلاثية العملة (§5.2).
- سجل الإعدادات: قراءة زمنية، سريان على الجديد فقط، إقفال بعد أول حركة، رسالة تأكيد + تدقيق (§2).
- سجل التدقيق: للقراءة فقط، محمي على مستوى ORM (§15.1).
- المستخدمون والأدوار والصلاحيات + ربط الفروع + فرض على الخادم (§3).
- الدخول: قفل بعد المحاولات، مهلة خمول، دعم المصادقة الثنائية (§15.2).
- واجهة عربية RTL كاملة + تبديل اللغة + الوضع الليلي + الهوية البصرية الرسمية لمنصتي (شعار، ألوان، خطوط).

### المرحلة 1 — النواة المحاسبية
- دليل حسابات هرمي بقالب افتراضي عربي (30 حسابًا) — الحسابات النهائية فقط تقبل الترحيل (§13.1).
- محرك القيد المزدوج: يرفض غير المتزن، يمنع الترحيل لفترة مقفلة، يفرض فصل المهام (§13.2, §13.6, §3.2).
- القيد المرحّل غير قابل للتعديل أو الحذف — التصحيح بقيد عكسي مرتبط بالأصلي (§13.5).
- ترقيم تسلسلي آمن للتزامن (قفل صف) لكل فرع ونوع (§16.22).
- خدمة أسعار الصرف: سعر مقترح + تعديل يدوي + سجل كامل + منع العملية عند غياب السعر (§5.3, §16.19).
- ربط عمليات §13 بالحسابات من جدول إعدادات (لا تثبيت في الكود).
- ميزان المراجعة بعملة الدفاتر، والفترات المحاسبية بفتح/إقفال باعتماد المالك.

### المرحلة 2 — الخزائن والحسابات البنكية
- كل خزينة وحساب بنكي كيان مستقل بعملة تُقفل بعد أول حركة، وله حساب أستاذ مخصص — الرصيد يُقرأ من دفتر الأستاذ (لا رصيد خارج السجل §1.1).
- الرصيد الافتتاحي يُسجَّل بقيد افتتاحي تلقائي.
- الحركات: إيداع، سحب، تحويل داخلي (نفس العملة)، تحويل بعملتين (مثال §6: الإمارات → مصر مع تسجيل فرق العملة تلقائيًا)، مصروف بنكي.
- حد اعتماد اختياري: التحويل فوق الحد يبقى بانتظار موافقة المالك قبل الترحيل.
- منع تعطيل خزينة/حساب عليه رصيد (§16.17)، وقفل العملة بعد أول حركة (§16.18).
- كشف حركة لكل كيان بعملته الأصلية مع الرصيد الجاري، ومطابقة بنكية يدوية (تعليم الحركات المطابِقة وعرض الفرق).

### المرحلة 2.5 — الشريحة الرأسية (بيع نقدي متكامل)
- منتجات ومخازن ودفعات مخزون (كل دفعة تحمل طريقة تقييمها)، واستلام مخزون بقيد تلقائي.
- نقطة بيع مصغّرة: شبكة منتجات + سلة حية + منع البيع تحت الحد الأدنى (يُتجاوز بصلاحية المدير ويُسجَّل في التدقيق).
- البيع النقدي يُنشئ قيدًا واحدًا متزنًا: درج الكاشير مدين، الإيراد دائن، تكلفة البضاعة المباعة مدين، المخزون دائن — ويُحسب COGS بطريقة FIFO من الدفعات.
- بيعة واحدة تظهر فورًا في: المخزون (نقص)، كشف الدرج (نقدية واردة)، وميزان المراجعة — متوازنة.

### المرحلة 3 — المخزون بعمق
- تقييم لكل دفعة: FIFO (الأقدم أولًا بتكلفتها) والمتوسط المرجح (متوسط المتاح) — تكلفة بعملة المخزن ومكافئ بالدرهم (§7.3، §7.5).
- تتبّع السريال (IMEI): يُطلب عند الاستلام والبيع، لا يُقبل سريال مكرر، ولا يُباع السريال مرتين (§16.14، §16.15).
- الجرد الدوري: فتح جلسة، إدخال الفعلي، عرض الفروق، اعتماد المالك ينشئ قيد تسوية (ربح/خسارة جرد).
- تنبيهات حد إعادة الطلب.

### المرحلة 4 — المشتريات والموردون والعُهد
- الموردون: لكل مورد حساب ذمة دائنة وكشف حساب بعملته، ورصيد يُقرأ من دفتر الأستاذ.
- فاتورة شراء (نقدي/آجل/من عهدة): تزيد المخزون وتُنشئ القيد حسب طريقة السداد.
- سداد المورد: جزئي مع تخصيص على الفواتير، وتسجيل فرق العملة المحقق تلقائيًا عند اختلاف السعر.
- أعمار الديون (0-30/31-60/61-90/+90) وتنبيهات المستحقات القريبة.
- العُهد (§12): صرف من خزينة، شراء/مصروف من العهدة، منع تجاوز الرصيد المتاح، إغلاق وإرجاع الرصيد، وتنبيه عهدة مندوب ترك العمل. المثال المعتمد: 5000 صرف − 3200 شراء = 1800 متاح.
- نقطة البيع: إدخال السريال (IMEI) للأصناف التي تتبعه، ومنع بيع السريال مرتين.

### المرحلة 5 — التحويل بين المخازن وتكلفة الوصول (§8)
- إذن تحويل بمراحل: مسودة ← في الطريق ← مستلمة ← مغلقة (الإلغاء قبل الإرسال فقط).
- الإرسال: تُخصم الكميات من المخزن المرسل وتنتقل قيمتها إلى «بضاعة في الطريق».
- تسجيل الشحن والجمارك (بند مستقل)، ويُرسملان في البضاعة في الطريق.
- توزيع المصاريف على الأصناف بالقيمة (الافتراضي) أو الكمية أو الوزن. المثال المعتمد: 3000+1000 وشحن 200 ← 150/50.
- الاستلام: تدخل البضاعة المخزن المستلم بالتكلفة الأصلية + نصيبها من الشحن والجمارك، محوّلة لعملة المخزن، مع تصفير حساب البضاعة في الطريق.
- الفروقات: النقص في الاستلام يُسجَّل كخسارة تلقائيًا. تقرير لكل إذن: التكلفة الأصلية، الشحن، الجمارك، التكلفة النهائية، وأقل سعر بيع مقترح.

### المرحلة 6 — المبيعات والعملاء ونقطة البيع بالورديات
- العملاء: لكل عميل حساب ذمة مدينة وحد ائتمان وكشف حساب. تجاوز الحد يمنع البيع الآجل إلا بصلاحية المدير.
- نقطة البيع: لا بيع بدون وردية مفتوحة، طرق دفع (نقدي/بطاقة/آجل)، اختيار العميل، شريط الوردية.
- الورديات: فتح برصيد افتتاحي، وردية واحدة لكل درج، إقفال بحساب العجز/الزيادة بقيد مستقل.
- ضريبة القيمة المضافة: تُفعَّل لكل فرع بنسبته من الإعدادات، وتُحسب على الفاتورة.
- التحصيل من العملاء يخفض الذمة. المرتجع يرد المخزون بتكلفته الأصلية ويعكس الإيراد (المادة 16-4).

### المرحلة 6ب — جهات التمويل (تابي/تمارا) والتقسيط
- البيع عبر جهة تمويل: تُسجَّل الذمة على الجهة (لا على العميل) بانتظار التسوية، دون دخول نقدية.
- التسوية اليدوية: يدخل المحاسب المبلغ المستلم فعليًا، ويُحسب الفرق عمولة تمويل، وتُقفل الذمة (تسوية عدة فواتير معًا).
- إعدادات كل جهة (نسبة العمولة/الرسم) بلا قيم افتراضية.
- التقسيط الداخلي: الفاتورة تحدد عدد الأقساط والمقدم، ويولّد النظام جدول أقساط، والتحصيل يُطبَّق على الأقدم أولًا، مع تقرير الأقساط المتأخرة.

### المرحلة 7 — التقارير ولوحة المالك (§14)
- لوحة المالك: النقدية والبنوك، قيمة المخزون، ذمم العملاء وجهات التمويل والموردين، صافي الربح، مقارنة الفروع، أحدث المبيعات.
- القوائم المالية: قائمة الدخل، الميزانية العمومية (متزنة)، كشف حساب عام لأي حساب برصيد جارٍ.
- المبيعات والربحية حسب المنتج (هامش الربح)، تقرير الضرائب، تقرير فروق العملة.
- إعادة تقييم فروق العملة غير المحققة عند الإقفال (قيد يُعكس تلقائيًا أول الفترة التالية).

### طبقة الأطراف (M4 / PTY)
- طرف واحد قد يكون شخصًا/مندوبًا/عميلًا/موردًا/جهة تمويل، وله **حساب فرعي لكل عملة** يُنشأ تلقائيًا عند أول حركة بتلك العملة.
- عمليات: صرف له، استرداد منه، صرف من رصيده، تحويل بين طرفين — مع دعم الصرف بعملة مختلفة وتسجيل فرق العملة المحقق.
- منع أي سحب/صرف يتجاوز رصيد الطرف في تلك العملة.
- تقرير **"أين المال؟"**: يجمع الخزائن والبنوك وأرصدة الأشخاص وجهات التمويل بكل عملة، مع إجمالي بعملة يختارها المستخدم.
- **ملخص الأطراف**: لكل طرف كم أخذ/ردّ/صرف/بقي بكل عملة (المتبقي = رصيد حسابه الفرعي).

### المرحلة 8 — التدقيق والصلابة
- الحالات الحدية (المادة 16) كاختبارات مسمّاة، وسيناريوهات القبول الشاملة E1–E9 كاختبارات آلية.
- فرض الصلاحيات على الخادم (كاشير يُمنع من الإعدادات/التقارير المالية/القيود بـ 403)، تجزئة كلمات المرور، قفل الحساب، سجل تدقيق غير قابل للتعديل.
- أمر نسخ احتياطي متسق + فحص سلامة بعد الاستعادة.
- **114 اختبارًا آليًا ينجح** عبر كل الوحدات.

### نقل البيانات (M13) — الأرصدة الافتتاحية
- قوالب Excel جاهزة لكل نوع: المنتجات، المخزون، الخزائن والحسابات، العملاء، الموردون، أرصدة الأشخاص (مع صفحة القيم المسموحة).
- رفع الملف → معاينة بحالة كل سطر (سليم/تحذير/خطأ) مع رسائل الأخطاء → لا ترحيل مع وجود أخطاء.
- الترحيل بموافقة المالك: يُنشئ الكيانات وأرصدتها الافتتاحية بقيود متزنة (الطرف الموازن: رصيد افتتاحي)، والعملية كلها أو لا شيء.

### إضافات مكمّلة
- أوامر الشراء (مسودة/معتمد/مستلم) وتحويلها لفاتورة بنقرة.
- عروض الأسعار وتحويلها لفاتورة مع إعادة التحقق من الحد الأدنى والمخزون.
- الدفع المقسّم في نقطة البيع (نقدي + بطاقة معًا).
- المرتجع الجزئي على مستوى السطر (كمية محددة من كل صنف).
- المحافظ الإلكترونية كنوع خزينة، وتغيير كلمة المرور المؤقتة عند أول دخول.
- مطابقة بنكية آلية برفع كشف Excel.

بيانات دخول إضافية للتجربة: محاسب `acc` / `acc123` (لاعتماد القيود التي ينشئها المالك — فصل المهام).
